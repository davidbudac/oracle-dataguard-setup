## Context for whoever runs this

### Lab (dbmint, KVM/libvirt)

| VM | IP | Role |
|---|---|---|
| `ol9_19_dg1` | 192.168.122.193 | PRIMARY `cdb1` (CDB, `db_domain=world`) |
| `ol9_19_dg2` | 192.168.122.194 | PHYSICAL STANDBY `cdb1_stby` (MOUNTED, SID `cdb1`) |
| `ol9_19_dg3` | (`virsh domifaddr ol9_19_dg3`) | FSFO observer `dg_observer` for cdb1 |

- The broker config `my_dg_config` runs in MaxAvailability with `LogXptMode=SYNC` and FSFO
  enabled (threshold 30 s). Flashback is OFF on the standby, so `dg_status.sh` and triage warn
  about it. That warning is real, not a bug.
- **Access:** `ssh db@dbmint`, then `ssh oracle@<IP>`. dbmint's key is authorised on the VMs;
  the Mac's key is not.
- **Environment:** in a non-login shell, export `ORACLE_HOME=/u01/app/oracle/product/19.0.0/dbhome_1`
  and `ORACLE_SID=cdb1` yourself.
- **VM control:** `virsh -c qemu:///system …`, run as user `db` on dbmint.
- **Sandbox:** if ssh "can't resolve" a host, the cause is the Bash sandbox, not the network.
  Retry with the sandbox disabled.

### Ground rules

- **Snapshot before anything that changes lab state** (Phase 0.1) and restore it after
  Phases 9 and 10.
- **Ask the user before each mutating phase (3-10).** Phases 1 and 2 are automated and build
  their own databases.
- **Never guess the cdb1 SYS password.** Ask the user, because failed SYSDBA logons are audited.
  It is only needed in Phases 4 (optional) and 9. The E2E pair uses `TEST_SYS_PASSWORD` from
  `tests/e2e/config.env`.
- **Do not stop, reconfigure or replace cdb1's existing observer (`dg_observer` on dg3).** Use
  the E2E `dgtest` configuration for observer tests.
- **Every test user you create must be dropped afterwards.** Remove temp files under `/tmp`
  on the VMs.

### How code reaches the lab

- **E2E:** the `deploy` phase does a git pull of `REPO_BRANCH` (`main`) from GitHub into
  `/home/oracle/dataguard_setup_tests` on both hosts. **Push fixes first**, then
  `bash ./tests/e2e/run_e2e_test.sh --only deploy`.
- **Ad-hoc runs of uncommitted code:** ship the working tree with
  `COPYFILE_DISABLE=1 tar --no-mac-metadata --exclude .git -cf - . | ssh db@dbmint "ssh oracle@<IP> 'mkdir -p /tmp/dgfix && tar xf - -C /tmp/dgfix'"`.
  Remove it afterwards.
- **Always run E2E with `bash` explicitly.** zsh breaks `SSH_OPTS` word splitting.

### The E2E pair

- `tests/e2e/run_e2e_test.sh` builds a **non-CDB** `dgtest` (primary, on dg1) and `dgtest_s`
  (standby, on dg2) via DBCA, next to cdb1.
- **Traditional mode** (no OMF/FRA).
- Phases: preflight, deploy, cleanup_previous, create_db, step1-7, step13, step9, step10,
  step11, cleanup_final.
- `--skip-cleanup` keeps the pair for Phases 3-9. `--from <phase>` and `--only <phase>` resume
  or select phases.
- Step 10 runs `fsfo/observer.sh` on the **standby** host.
- Step 11 **skips itself** when the empty test DB has no user services. Trigger coverage
  comes from Phase 5.

## Phase 10: Open OMF control-file question (~1 h, decides a fix)

The question: in OMF mode, step 5's `DUPLICATE … SPFILE` sets no `CONTROL_FILES`, so it
probably copies the primary's explicit `control_files` to the standby. This is the same class
of problem as H10.

1. Restore the snapshot, rebuild the non-OMF `dgtest` primary (`--only create_db`), and run
   steps 1-4 by hand. In step 2 choose **OMF** mode.
2. Before step 5, record the primary's `show parameter control_files`.
3. Run step 5; afterwards record the standby's `control_files` and where the files actually are.

**Outcome:**
- Files under `db_create_file_dest`: no fix needed. Close the item in the review doc.
- Files at the primary's paths, or RMAN failing with ORA-19504/ORA-27040: implement an explicit
  `SET CONTROL_FILES` in step 5's OMF branch, plus the directory in step 3, plus a unit test.
  Then rerun this phase.
